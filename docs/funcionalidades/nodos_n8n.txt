# Documentación del Flujo n8n (Auditoría Paso a Paso)

## 1. Nodo: Telegram Trigger
- **Función:** Captura el evento (webhook) cuando un usuario envía un mensaje al bot de Telegram.
- **Salida / Output:** Un array JSON con la información del mensaje.
- **Valores clave que extraemos de aquí:**
  - `chat_id` (ruta: `message.chat.id`): Ej. `2087025697`. Este es el identificador único del usuario. Se usará en los próximos nodos de Redis para agrupar sus mensajes y en los HTTP Requests como `cliente_telefono`.
  - `texto` (ruta: `message.text`): Ej. `"Hola Buen Dia"`. Es el mensaje literal que nos envió.

## 2. Nodo: Iniciar o Meter Valor (Redis)
- **Función:** Guarda el texto del mensaje entrante en la memoria temporal de Redis.
- **Operación:** `Set` (Guardar/Establecer un valor).
- **Clave (Key) estructurada:** `mensaje:{{ $json.message.chat.id }}:{{ $json.message.message_id }}`
  - *Ejemplo en vivo:* `mensaje:2087025697:125`
- **Valor (Value) guardado:** `{{ $json.message.text }}` (Ej: `"Hola Buen Dia"`)
- **⚠️ Observación Crítica:** Estás guardando cada mensajito como una clave totalmente nueva e independiente en Redis (porque usas el `message_id` en la clave). Esto significa que si el cliente manda 3 mensajes seguidos, tendrás 3 claves distintas en Redis (ej: `mensaje:123:1`, `mensaje:123:2`, `mensaje:123:3`). Lo anoto porque va a afectar cómo configuraremos el nodo de limpiar Redis al final.

## 3. Nodo: Incrementar a 1 (Redis Increment)
- **Función:** Lleva la cuenta de cuántos mensajes rápidos mandó el usuario en esta misma "ráfaga" de tiempo.
- **Operación:** `Increment` (Suma 1 al valor numérico actual. Si no existe, la crea con valor 1).
- **Clave (Key) utilizada:** `esperando:{{ $('Telegram Trigger').item.json.message.chat.id }}`
  - *Ejemplo en vivo:* `esperando:2087025697`
- **Salida / Output:** Devuelve el valor numérico actualizado de la clave. En la captura vemos que devuelve `1`.
- **⚠️ Observación Crítica:** Esta es la **segunda clave** importante que se crea por usuario. Al final del flujo, obligatoriamente vamos a tener que borrar esta clave (`esperando:CHAT_ID`) para que el contador vuelva a cero en su próxima interacción.

## 4. Nodo: If (Condición de agrupamiento)
- **Función:** Evalúa si el mensaje que acaba de entrar es el primero de la ráfaga (el que inicia el temporizador) o si es un mensaje secundario.
- **Condición configurada:** Verifica si el primer valor del JSON entrante (el contador) es igual a `1`.
  - *Expresión usada:* `{{ Object.values($json)[0] }} Is equal to 1`
- **Camino True (Verdadero):** Como el contador devolvió `1`, la ejecución se fue por acá (exitoso). El flujo sigue vivo y pasa al nodo `Wait`.
- **Camino False (Falso):** Si el usuario hubiese mandado otro mensaje un segundo después, el contador habría dado `2` y se iría por el camino falso (que detiene el flujo silenciosamente). Esto es exactamente lo que evita que la IA responda 5 veces si el cliente manda 5 mensajitos cortos.

## 5. Nodo: Wait (Temporizador)
- **Función:** Pausa la ejecución del primer mensaje por una cantidad de tiempo definida (6 segundos). Esto le da tiempo al usuario de enviar más mensajes que serán atrapados y guardados en Redis por las ejecuciones que "mueren" en el nodo `If`.
- **Salida / Output:** Simplemente deja pasar el flujo sin alterar los datos.

## 6. Nodo: Extraer todos los mensajes (Redis Keys)
- **Función:** Una vez terminada la espera, busca en Redis TODOS los mensajes que el usuario haya enviado en esa ráfaga.
- **Operación:** `Keys` (con la opción `Get Values` activada).
- **Key Pattern:** `mensaje:{{ $('Telegram Trigger').item.json.message.chat.id }}:*`
- **Salida / Output:** Devuelve un único objeto JSON donde las propiedades (keys) son los nombres de las claves de Redis y los valores son los textos de los mensajes.
  - *Ejemplo en vivo:* `{"mensaje:2087025697:125": "Hola Buen Dia"}`
- **⚠️ Observación Crítica:** ¡Este nodo tiene oro! Al activar "Get Values", nos está devolviendo exactamente la lista completa de las claves que necesitamos borrar después (los nombres de las propiedades de este JSON).

## 7. Nodo: Armar Mensaje (Set)
- **Función:** Toma todos los mensajes sueltos que trajo Redis y los une en un solo bloque de texto.
- **Expresión usada:** `{{ Object.values($json).join("\n") }}`
- **Cómo funciona:** `Object.values($json)` agarra todos los textos (ignorando los nombres de las claves) y `.join("\n")` los pega uno debajo del otro separados por un salto de línea.
- **Salida / Output:** Devuelve un JSON muy limpio con un solo campo:
  - `mensaje_completo: "Hola Buen Dia"`
- **Resultado:** Este es el súper-mensaje consolidado que finalmente se enviará al Agente de IA para que lo procese de una sola vez.

## 8. Nodo: Preparar Borrado (Code)
- **Función:** Como el nodo anterior olvidó los nombres de las claves, este código busca el historial del nodo 6 y arma una lista con todas las claves exactas que hay que eliminar.
- **Configuración:** `Mode: Run Once for All Items`
- **Código:**
  ```javascript
  const chat_id = $('Telegram Trigger').first().json.message.chat.id;
  const mensajesJson = $('Extraer todos los mensajes').first().json;
  let claves_a_borrar = Object.keys(mensajesJson);
  claves_a_borrar.push(`esperando:${chat_id}`);
  return claves_a_borrar.map(clave => ({ json: { clave_a_borrar: clave } }));
  ```
- **Salida / Output:** Devuelve una lista de ítems (array de JSONs), uno por cada clave a borrar. 
  - *Ejemplo en vivo:*
  ```json
  [
    { "clave_a_borrar": "mensaje:2087025697:125" },
    { "clave_a_borrar": "esperando:2087025697" }
  ]
  ```

## 9. Nodo: Redis Delete
- **Función:** Ejecuta un Delete por cada uno de los ítems que le mandó el nodo Code. ¡Limpieza absoluta del buffer y contador a cero!
- **Operación:** `Delete`
- **Key:** `={{ $json.clave_a_borrar }}`
